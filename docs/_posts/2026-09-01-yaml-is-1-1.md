---
title: Ruby's YAML is 1.1, and it matters
summary: yes is a boolean, 010 is octal, and 1e3 is a string.
tags: [yaml, fidelity]
---

Every Rust YAML crate implements YAML 1.2. Ruby's Psych implements **1.1**,
and Jekyll's output depends on the difference.

Under 1.1, `yes`, `on` and `true` are all booleans; `010` is octal 8; `1_000`
and `1,000` are both 1000. So a `_config.yml` containing

```
future: no
port: 010
```

means `false` and `8` in Jekyll, but `"no"` and `10` under a 1.2 parser.

The catch is that the rules are not the tidy set the spec implies. Psych runs a
"looks like prose" guard *first*, short-circuits anything longer than five
characters, and applies its numeric patterns only to plain — never quoted —
scalars. The result has sharp edges:

| scalar | Psych |
|--------|-------|
| `yes` | `true` |
| `"yes"` | `"yes"` (quoted scalars are never resolved) |
| `010` | `8` |
| `0o17` | `"0o17"` (Psych has no `0o`) |
| `1,000` | `1000` |
| `1e3` | `"1e3"` — the float pattern requires a `.` |
| `1.0e+3` | `1000.0` |
| `1:30` | `5400` (sexagesimal) |

`1e3` is the one nobody would guess.

So rekyll parses to raw parser events and ports Psych's own resolution rules
over the scalar text, keeping quoted-versus-plain information that a normal
YAML crate discards. It is checked scalar by scalar against Psych itself; of
52 cases only two differ, and both are inputs where Psych raises.
